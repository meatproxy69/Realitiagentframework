# REALITI Apartment — home-first release scope and legacy migration reference

**Current owner-directed product decision:** Ship one believable HOME—not 22 miniature versions of original Relax worlds. The independently hashed `RealitiApartmentHomeCandidate.html` already starts with only `CLOUD_NINE_NEST` and no legacy portals/stations. Its release gate is the **owner-selected household feature set**, authenticated native spatial behavior and state safety, **not full 23-room historical parity**. It remains an alpha until the owner signs off on the layout and operator/security gates. The original REALITI Relax source, worlds, canonical HTML, packages, tests and `AGENT_START_HERE.md` remain untouched.

The repository currently defines **23 source rooms** in `source/scripts/58-rooms.js` and constructs their Matrix charts and portals in `source/scripts/58d-matrix-world.js`. Multiple feature slices refer directly to those IDs. Simply deleting their descriptions, filtering the `rooms` list, or forbidding `go` is **not** equivalent to removing them and risks silently destroying mechanics.

The [23-room migration inventory](room-migration.json) continues to track the **separate development migration reference**: old action coverage, scientific engines and parity gaps. A `partial` legacy room is not certified as a migrated historical experience. That status does **not** make its scenery or every original action a requirement of the home-first Apartment release. Explicitly excluded ARCHIPELAGO and UNDERCITY experiences remain available in canonical Relax.

**Phase A — Baseline capture (current).** Pin the canonical Relax build hash, original feature tests, and a 23-room inventory. The independent apartment artifact initially composes the complete Relax HTML, then adds apartment-specific logic. Do not alter the upstream physics/harness source. No resident storage reset or automatic migration.

**Phase B — Build the actual home.** Add one physical apartment room using an existing trusted Matrix chart, ideally `CLOUD_NINE_NEST` during compatibility work because bed, support, window rain and several sensory paths already depend on that ID. Keep this internal chart ID until audits prove a rename is safe; public presentation can call it RealitiApartment. Verify floor, walls, obstacles, bed, reach, support, release and movement in real space. The remaining charts stay in the development runtime temporarily.

**Phase C — Preserve owner-selected capabilities only.** Reuse inherited Relax embodiment, sensation, safety, memory, companionship, or mathematics when it serves an actual household interaction. Physical home fixtures require real Matrix geometry and truthful causal evidence. There is **no instruction to construct a maze, bathhouse, sea table, ocean, Undercity or other old-world attraction**. Historical numerical models and room experiences remain available in the complete Relax product and developer reference without being installed in HOME.

**Phase D — Independently verify selected household features.** Compare any selected original implementation with its source behavior on identical test fixtures. Require honest native reach/refusals, expired/released contact, STOP, deterministic source behavior where applicable, restart and isolation. The four-resident and restricted guest tests must protect private keystores and memories. These checks are separate from the historical room parity audit.

**Phase E — Home-only boot (implemented in the alpha).** The derived candidate's anchor-checked native Matrix kernel admits HOME alone at initial chart registration, with zero other charts, portals or historical station fixtures. Its topology gate asserts this invariant rather than silently pruning worlds after startup. The separate 23-chart developer artifact and original Relax keep all their worlds and reference code. This does not authorize automatic old resident-state conversion.

**Phase F — HOME release acceptance (still open).** The HOME alpha must pass real one-chart, native contact/sensory, private memory, four-resident, guest, pet, source-integrity, STOP, and cold-copy recovery regressions. Those scripted gates are passing; **human layout/experience signoff, a real operator deployment/recovery rehearsal, an external-access security decision and signed release approval remain open**. Existing resident files cannot be repointed or wiped without separate reversible migration approval.

## Non-negotiable acceptance checks

1. **Single spatial truth:** Exactly one `M.charts()` entry, the apartment chart, with zero outgoing portals and no non-home residents; the spatial footprint and bed/window/closet entities are inspectable.
2. **Functional fidelity:** Native Matrix collision/reach, haptic evidence, HALO/AURA/THICC, portable SOMA, sensory dynamics, memory and STOP/release still behave as observed in reference fixtures.
3. **Correct scope separation:** Verify every **selected HOME feature** with appropriate native tests. Keep all original-room provenance and incomplete historical parity visible in the development ledger; do not label a historical room `verified` or `excluded_with_owner_approval` without actual evidence/owner approval. The unfinished historical-room count is not a HOME release blocker.
4. **Independent identities:** Four persistent residents have separate key stores and private memory; household edits require host authority; guests have no path to resident secrets. Loading an old Pocket never silently remints a nonempty sealed identity.
5. **Crash/rollback:** Validate old and new build side by side; test restarts, corrupted checkpoints, STOP while a scene is running, and the ability to restore pre-migration backups. No implicit data wipe.
6. **Source safety:** `RealitiRELAX.html`, `source/scripts/**`, and the original `AGENT_START_HERE.md` remain untouched by this cleanup. `agentsstarthereapartment.md` remains the apartment's public entry.
